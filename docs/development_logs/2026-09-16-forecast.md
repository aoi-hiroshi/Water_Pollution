# 2026-09-16：接入 Attention-LSTM ONNX 趋势预测

## 需求与范围

将“预测任务2 - 副本”的现有预测模型接入 Qt → Muduo → Controller →
Service → Repository/DbExecutor → 推理线程池的分层框架。
保留离线训练文件，不恢复 Flask，不改 QSS 或模型权重。
本次未自动建表、导入数据库或连接 Linux 虚拟机。

## 设计决策

- 选择 `prediction_test.ipynb` 的120条历史、10步预测版本。
- 权重使用 `best_model_four_head_h10_diff.pth`，配套 `scaler_y.pkl/scaler_aux.pkl`。
- 预测输入顺序：COD、氨氮、总磷、浊度，再接六个辅助特征，与分类不同。
- 标准化、残差 Attention-LSTM、反标准化包含在同一个ONNX图里。
- float32物理量 `[1,120,10]` → `[1,10,4]`，校验形状/类型/元数据协议和版本。
- SQL限定同公司、数据表、截止ID，查最近120条后逆序。
- 预测与分类共享有界CPU推理队列，不占用数据库连接执行模型。
- 新增DbExecutor错误回调，覆盖任务获得连接之前的异常。
- 当前无真实采样时间协议，返回步数，不假装为小时。
- 不展示虚构的在线误差、置信区间和告警阈值。

## 交付内容

服务端：预测领域数据、Forecaster接口、ONNX适配器、ForecastService、
Repository历史窗口查询、Controller状态/预测接口、main/config/CMake装配。

客户端：PredictionService与重写的PredictionPage，支持真实公司列表、
截止样本ID、1～10步、四指标切换、历史/预测曲线、结果表格、CSV和错误提示。

导出：独立推理架构、exporter、版本清单，及已生成的ONNX、manifest、黄金样本。
只提取原Notebook的三个已核对模型类作参考，不运行训练/绘图单元。
全部数值检查通过后才替换目标模型，原checkpoint/scaler未修改。

## 环境问题及处理

Windows首次加载到系统内旧ONNX Runtime1.17.1，与1.20.1头文件不一致。
临时测试目录放置匹配版本DLL后解决。Linux也需核对SDK、动态库版本
及实际加载路径。Windows语法检查使用MinGW调用约定兼容定义，
不表示Muduo网络服务支持Windows。

原训练环境执行与ONNX原生文件读取被沙箱阻止，获准执行本地验证后通过。
未通过修改模型或放宽检查规避限制。
